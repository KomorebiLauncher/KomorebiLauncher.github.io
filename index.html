Komorebi Launcher

こもれび ランチャー

基于 Prism Launcher 的开源 Minecraft: Java Edition 启动器，为国内网络环境做了下载镜像、Java 自动配置与 OptiFine 支持。

「Komorebi」写作「木漏れ日」，是从枝叶之间漏下来的日光ですわ。

端書き

ごきげんよう，初次见面的各位ですわ。开头请容我先划一条线ね：这是一个非官方的启动器，与 Mojang、Microsoft 都没有隶属关系，也没有得到它们的批准或背书ですの。这一条要是读漏了，我可是会ちょっと困扰的哦。

下面写的，除了标明「主干」的第参节，都是已发布的 0.2.2 此刻实际在做的事ですわ；将来也许会做的事，我一概不写。だって读史料的人，最怕把「打算做」当成「做过了」——写自己的东西时，也是一样的ですもの。

壱

なにを解くか要解的，是哪三件事呢

国内玩家用通用启动器时，最常碰上的是三件事ですわ：Mojang 的下载端点慢，或者干脆连不上；Java 运行库得自己去找；模组与整合包的下载入口又不好用。まあ，三件都叫人头疼呢。

常听人说「换一个国内的启动器就好了」。あら，我倒不讨厌这种说法よ？只是它一句话就把三件事揉成了一件，这就叫人为难了ですの。三件事各有各的缘由，该补的地方也各不相同ですもの。

所以 Komorebi Launcher 起初并不去动上游的功能结构，只在这三处分别补齐；如今那套结构本身也开始翻修了（见第参节）ですわ。不变的是，所有下载都只发生在玩家自己的机器与官方端点（或玩家自己开启的镜像）之间。补得少一些不要紧，补错了地方才要紧——这一点，我是ぜったい不肯让步的ですわよ。

弐

いまできること眼下已经做得到的事

  • 实例管理每个实例都有自己的 .minecraft 目录、设置与图标，Minecraft 本体与加载器按组件装拆，也能导入导出ですの。模组、资源包、光影包、数据包、存档与写真截图都在实例里直接管理，可以从 Modrinth 与 CurseForge 搜索安装，已装的模组会逐个去来源站点比对有无更新。作者不允许第三方启动器转发的模组文件，默认不去别的源补下载；这个选择写在设置里，默认关闭。作者都说了「不」ですもの，我便不替作者去取ですわ。
  • 下载镜像默认是关着的ですわ，游戏本体、库与资源都走 Mojang 的官方地址。在设置 → API 里打开之后，三类内容可以各自配置镜像源与尝试顺序；哪个源失败了，就按顺序换下一个，官方源始终留作最后一道ね。细节写在第肆节，请ぜひ翻过去看看♪
  • 爪哇Java 自动配置按 Minecraft 与加载器的版本要求，自动挑选或下载 Java 运行库，下载时先试清华大学开源镜像站的 Adoptium 镜像。可以限定允许的 Java 版本区间，也可以把 Java 放进实例目录里优先使用。版本是实际把程序跑一遍问出来的，不看目录名去猜ですの——だって目录名这种东西，谁都能随手改ですもの。
  • 内存与 JVM 参数建议按这台机器的内存和这个实例的模组数量，给出堆该开多大，也能一键填入垃圾回收参数。填的时候会留下你自己写过的参数，只替换建议要覆盖的那同一项。别人亲手写下的东西，整段抹掉可就太失礼了ですわ。
  • 启动失败诊断游戏没能启动时，去读它留下的日志，认出到底是哪一条：内存不足、Metaspace 不足、Java 版本与模组不匹配、模组重复或缺依赖、mixin 失败、显卡驱动打不开窗口、纹理图集溢出……再给出对应的改法ですわ。日志这孩子ね，是不会自己开口的；得先备好要问它的话才行ですの。
  • 服务器列表实例里的服务器按 SLP 协议去问一声，显示在线人数、游戏版本与延迟。鼠鼠标停在一行上，能读到服务器自己的挨拶欢迎语。うふふ，这一处，我私下里とっても喜欢呢。
  • OptiFine在版本页直接浏览并安装 OptiFine。安装用的就是 OptiFine 官方安装器本身，启动器只负责下载、在临时目录里运行它、再把结果收回来ですわ。OptiFine 的补丁逻辑，我一处也没有抄，也没有重写——这种事，淑女是不做的ですの。
  • 加载器与整合包NeoForge、Forge、Fabric、Quilt、LiteLoader，与上游一致ですわ。整合包可以从 Modrinth、CurseForge、ATLauncher、FTB、Legacy FTB、Technic 安装，也能导入 .mrpack 与 MultiMC、PolyMC 导出的压缩包よ。
  • 中文界面简体中文完成度 100%ですわ！翻译放在本组织自己搭的静态源（komorebilauncher.github.io/i18n/）上，启动时先校验文件哈希再加载。実は我当初ね，就是因为想玩的游戏没有中文，才开始做翻译的；所以这一项，我絶対に不会马虎哦。
参

普請中正在翻修骨架这件事

「普請」原是寺里请众人一同动手修造殿堂的意思ですわ。启动器眼下正在换骨架，でも我不想等完工了才说の。

这一节写的，都已经合进主干，每次推送都由 CI 在各平台上构建ですの；只是还没有发布成正式版本，装着 0.2.2 的玩家暂时还碰不到ね。想先尝鲜的人，可以到仓库的 Actions 页面取开发版构建（需要登录 GitHub；它们没经过发布前的检查，坏了请ぜひ告诉我ね）。

  • 新的内核层：上游的实例、版本与启动代码和界面缠在一起，改一处，常常要牵动一大片——もう，真是缠得乱七八糟ですわ。所以我在旁边另起了一层 launcher/komorebi/，里面不引用任何窗口部件，只交出朴素的数据：实例型録清单；版本清单的读取与继承链的合并；启动命令行的拼装；Java 的发现与挑选（主版本相同者优先，否则取高于要求的最小版本）。这些规则，都用不依赖游戏、Java 与网络的单元测试牢牢钉住了ですの。
  • 已经接上的部分：主窗口的实例列表已经改由内核层提供，工具栏、献立菜单与快捷键照旧作用于所选的实例。启动这一路，目前只在开发用的探针里走通ですわ：原版实例已能由内核层挑 Java、拼命令行，真正启动起来。带模组加载器的实例还读不了——读不了，就如实说读不了ですの，けっして不会丢下模组、只把游戏启动起来。界面上的「启动」釦按钮，仍走原来的路径よ。
  • 大正浪漫ロマン的外观：主题已经内置进程序，浅色一套，再用同一幅画做出深色的一套；另配一套照启动器自己的线条语言画的图标，墨色与月色两种。实例改用歌留多卡片显示；窗口有三种布局，可以在外观设置里即时切换：默认的侧栏、只留图标的窄栏、把实例操作移到顶部的横栏。主窗口的背景图、显示方式、压暗程度、文字颜色与描边，也都可以自己设ですわ。说是「大正浪漫ロマン」，実は只是把我自己喜欢的东西一样样摆了进去而已ですの，うふふ。
  • 国内整合包：HMCL 与 MCBBS 格式的整合包可以导入了ですわ，压缩包里的内容会完整还原。清单里要求另行下载的文件（MCBBS 用 CurseForge 文件 ID 声明的，以及两种格式里的直链），会在交出实例之前取回；给了 SHA-1 的，逐一校验；CurseForge 已不再提供的，数清楚后告诉你ね。从本地选来的整合包，和 CurseForge 整合包一样，先列出未经审查的模组请你确认；清单里想写到目标目录之外的路径，一律拒绝——あら，想偷偷溜出门去？那可不行ですわ。
肆

鏡のしくみ镜子只换主机，不换内容

「镜」这个字，在读神话的人眼里分量很重ですのよ，八咫镜可是要照出神本身的。这里的镜子嘛，不过是一面硝子玻璃镜，朴素得多ですわ。

镜像只做一件事ですの：把下载请求换到另一个主机上的同一份文件。换法按内容类型固定，而且只对 Mojang 自己的主机生效。按表列在下面ね。

内容官方主机镜像上的位置
版本清单、客户端 jar、Java 运行库piston-meta / piston-data / launcher / launchermeta镜像根路径，目录结构不变
资源文件（assets）resources.download.minecraft.net镜像的 /assets 前缀
支持库与加载器库libraries.minecraft.net 等 maven 主机有序的前缀列表，逐条尝试

镜像默认是关着的ですわ。镜像未必更快ですもの，所以我不擅自替你打开；要用，请到设置 → API 里切换。内置的镜像源是 BMCLAPI 与三所教育网镜像的 maven 树。自动下载 Java 运行库另走一路：先试清华大学开源镜像站的 Adoptium 镜像，文件与官方的 SHA-256 一致；只带版本参数、不带文件名的 api.adoptium.net 入口，暂时仍走官方。Modrinth、CurseForge 等内容平台的主机不在重写范围内，它们的文件始终从各自的官方端点下载。所有下载都会按元数据里给定的哈希校验；镜像若返回了不对的内容，就当作校验失败，不会默默收下——来路不明的东西，我可不收の。

伍

名乗り向谁报上名来

报上名来，要对方信得过才算数ですわ。下面三种账户的区别，说到底就在于「向谁报名」ね。

  • Microsoft 账户：走标准的 OAuth 2.0（授权码 + PKCE 与设备码两种流程，登录窗口里两种都有），随后按官方流程换取 Xbox Live 与 Minecraft Services 的令牌，读过账户的游戏所有权信息之后，才提供启动ですわ。微软登录用的是本组织自己注册、已于 2026-11-06 通过 Mojang 审核的那个 AppID，它随程序一起内置，装好就能登ですの——不必自己申请，也没有要你填的地方ですわ；只有做衍生构建、换用自己申请到的 AppID 时，才去设置里覆盖它（分发衍生构建的话，请自行申请ね）。登录之后，还可以上传皮肤、选择外套披风♪
  • 离线账户：明明白白的本地身份，只在本机生成玩家名与 UUID，用于单机世界与允许离线玩家的服务器。它不向 Microsoft、Realms 或需要正版验证的服务器认证，也拿不到任何 Microsoft 或 Minecraft 令牌；在线会话失败或过期时，也不会退回成离线账户ですわ。与上游 Prism 相同，要先添加一个拥有 Minecraft 的微软账户才能新建；启动与下载，以拥有游戏的微软账户或第三方验证账户为准。这道门槛，是我刻意留着的ですのよ。
  • 第三方账户：向玩家自己填写的身份验证服务器（运行 authlib-injector 或同类实现的服务器）换取游戏令牌。地址请填服务器给你的那个验证地址，启动器会在它下面接上 authserver/authenticate 这类路径，不需要、也不应该自己补全ですわ；以 LittleSkin 为例，填它给出的形如 https://littleskin.cn/api/yggdrasil 的地址就好よ。账户上有多个角色时，第一次登录会先问你要哪一个，之后每次都按这个选择去要。令牌与角色名保存在本地；服务器拒绝登录时，原样显示它自己给出的理由。ただ，有一点要先说清楚ですわ：登录凭据以明文保存在本机的账户文件里，因为这个协议只在换取令牌时接受账号密码ですの。实例还需要 authlib-injector 代理，用这类账户启动时，启动器会先问过你，再代为装成实例组件ね。

For the Minecraft / Mojang app review team

写给 Mojang 应用审核的英文书信ですわ，请点开阅读ね

What this is. Komorebi Launcher is a free, open-source Minecraft: Java Edition launcher for players in mainland China, a GPL-3.0 derivative of Prism Launcher. Everything is published in the repository linked above; there is no closed or obfuscated component, and no binaries are hosted anywhere else.

Current status. Our own application (client) ID was approved by Mojang Enforcement on 2026-11-06, confirmed by completing the full chain against the live services rather than by reading the notification, which is a batch email that names no application. The approved ID is compiled into the launcher, so a player installs the program and signs in: nothing has to be registered or typed in. An override exists only for derivative builds that hold an application of their own. This section documents the design that approval applies to.

The authentication chain we implement. Authorization code with PKCE, or the device code flow, against the Microsoft identity platform. The launcher requests Xbox access, obtains the Xbox Live and XSTS tokens, exchanges them at login_with_xbox, and checks the player's Java profile and Minecraft license. A Microsoft account counts toward launching or downloading only when that check passes. The tokens it is issued are kept in the launcher's local account file so the player does not sign in on every launch, and are sent only to the official Microsoft, Xbox Live and Minecraft Services endpoints. It does not use those endpoints to obtain game content for redistribution.

Why our own ID rather than an existing one. Upstream Prism Launcher's source states that a derivative work must ship its own credentials. Using another project's application ID would attribute our traffic to them and leave them unable to revoke it; we hold our own.

Load on your servers and CDN. API calls happen only when a player opens an account, browses, or launches. One game file download per version per player, from Mojang's own endpoints. No crawling, no bulk indexing, no background polling, and no redistribution of downloaded files from our side — the mirrors we ship rewrite Mojang-hosted file URLs only, and are used solely by the individual player who enables them. (Separately, the Java runtime downloader prefers a university mirror of Eclipse Adoptium, whose files match Adoptium's published SHA-256.)

Local profiles, stated plainly. Offline profiles are explicitly local identities for singleplayer worlds and for servers that allow offline players. They do not authenticate to Microsoft, Realms, or servers that require online accounts, and they receive no Microsoft or Minecraft token. One can be created only after an account that owns Minecraft has been added, and a failed or expired Microsoft sign-in never falls back to an offline profile. Separately, a player may point the launcher at a server operator's own authentication service; that service is added by the player, never contacts Microsoft, and is not part of the Microsoft sign-in path.
